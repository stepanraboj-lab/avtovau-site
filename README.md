# AutoVau

Публичный сайт статический. Источник данных автопарка — `fleet.json`. Публикация по-прежнему использует `site.zip`.

- `fleet/templates/` содержит общую оболочку страницы, шаблоны главной, карточки каталога и страницы автомобиля, а также локальные значки способов связи.
- `fleet/assets/fleet.css` содержит общие стили страниц. Модальное окно и прямые контакты используют прежние локальные ресурсы из архива.
- `fleet/build.py` генерирует HTML, карту сайта и общий CSS в архиве. Исходные фотографии и прочие ресурсы берутся из текущего архива. Генератор использует только стандартную библиотеку Python 3.10+.

## Обновление автопарка

1. Откройте `fleet.json`. Найдите автомобиль по `id`.
2. Для цены измените `daily_rub` нужного периода в `tariffs`. Поле `days` задаёт нижнюю границу тарифа. Главная использует запись с `days: 30`.
3. Для статуса задайте `available` (доступен), `unavailable` (временно недоступен) или `rented` (в аренде). Для `rented` заполните `rented_until` в формате `YYYY-MM-DD`. Для остальных состояний укажите `null`. Дата сама по себе статус не меняет.
4. Для оборудования используйте `true` (есть), `false` (подтверждено отсутствие), `null` (неизвестно). Общие принадлежности находятся в `common_equipment`. Характеристики каталога, страницы и JSON-LD обновляются из файла данных.
5. Выполните команды из корня репозитория.

```bash
python3 fleet/build.py
python3 fleet/build.py --check
unzip -tq site.zip
```

Для проверки в браузере распакуйте архив в отдельный временный каталог и запустите сервер из корня распаковки.

```bash
preview_dir=$(mktemp -d)
unzip -q site.zip -d "$preview_dir"
python3 -m http.server 8000 --directory "$preview_dir"
```

В PR включите изменённые исходники и пересобранный архив.

## Добавление автомобиля

1. Скопируйте запись в `vehicles`. Задайте новый уникальный `id` из строчных латинских букв, цифр и дефисов, а также адрес `/cars/<id>/`.
2. Заполните модель, год, характеристики, описания, статус, тарифы, минимальный срок, лимит пробега и условия только по подтверждённым данным. Укажите тариф на 30 дней. Сохраните все ключи в `equipment`, используя `null` для неизвестных значений.
3. Добавьте оригиналы снимков в `assets/` архива. Например, из папки, содержащей новые файлы в `assets/`, выполните `zip /абсолютный/путь/к/site.zip assets/имя-файла.jpg`. Укажите эти пути и описательные `alt` в `photo` и `gallery`.
4. При изменении фотографий обновите WebP командой `python3 fleet/prepare-images.py` в окружении с Pillow. Затем пересоберите архив через `python3 fleet/build.py` и проверьте главную, карточку, контакты, фото и карту сайта. Генератор добавит страницу и canonical в соответствующие места. Действующий workflow проверяет обязательные файлы текущего автопарка.

## Проверки перед PR

```bash
python3 fleet/build.py
python3 fleet/build.py --check
```

## Бронирование и расчёт

Сутки считаются как разница между датами окончания и начала. Например, с 10 по 11 декабря получается одни сутки. Прошедшие даты определяются по времени Москвы. Срок короче `minimum_days` отклоняется. Применяется ставка с наибольшим порогом `tariffs[].days`, не превышающим выбранный срок. Её умножают на все сутки. Окно показывает аренду, возвратный депозит и общую сумму отдельно. Статус из автопарка справочный, даты сами по себе не меняют его.

Telegram и WhatsApp получают текст в параметре ссылки при переходе. Сайт не отправляет сообщения и не создаёт заявки. Без JavaScript остаются прямые ссылки в блоках контактов.

Общие условия всех машин находятся в `fleet.json → rental_terms`. Для конкретной машины меняйте `minimum_days`, `daily_km`, `overage_rub` и `deposit.rub`. Генератор подставляет их в общий шаблон, FAQ и окно бронирования. При согласованной смене условий обновите ожидаемые значения в `fleet/tests/check.py`.

## Яндекс Метрика

1. Согласуйте с владельцем цели, сроки хранения, порядок согласия и опубликованную политику. В репозитории есть [технический аудит и вопросы для владельца](docs/privacy-draft.md). Проект пользовательской политики генерируется из `fleet/templates/privacy.html`.
2. В настройках счётчика оставьте Вебвизор, карты кликов и автоматическое отслеживание ссылок выключенными. Не включайте передачу URL с данными клиентов и автоцели с содержимым форм.
3. Доведите текст политики до утверждённой редакции и только затем установите `legal.policy_approved: true`. Счётчик `114645808` и путь `/privacy.html` уже указаны в `analytics`. Пока политика не утверждена, браузер не получает ID счётчика. Значение `analytics.counter_id: null` также отключает аналитику.
4. Сверьте существующие цели типа **JavaScript-событие** с идентификаторами ниже. Обработчики счётчика работают после явного согласия. Выбор можно изменить через кнопку «Настройки cookies» в подвале, отказ прекращает работу счётчика на последующих загрузках.
5. Проверяйте принятие, отказ, отзыв, сохранение выбора и вызовы целей в изолированной сборке с подменой тега или отдельным тестовым счётчиком. Не отправляйте контрольные конверсии в действующий счётчик.

| Цель | Действие |
|---|---|
| `vehicle_view` | Один раз при старте аналитики в открытом документе карточки. Перезагрузка считается новым просмотром. |
| `booking_open` | Открытие диалога конкретного автомобиля. Повтор в течение 650 мс подавляется. |
| `booking_dates` | Изменение на полную допустимую пару дат. Соседний повтор пары подавляется, промежуточный и невалидный ввод игнорируется. |
| `booking_quote` | Первый полученный расчёт по каждой допустимой паре дат в открытом документе карточки. Другая пара считается новым расчётом. |
| `contact_telegram` | Клик по ссылке Telegram. |
| `contact_whatsapp` | Клик по ссылке WhatsApp. |
| `contact_phone` | Клик по ссылке набора номера. |
| `contact_avito` | Клик по ссылке профиля Авито. |
| `vehicle_share` | Успешное завершение системного действия «Поделиться» или копирование через Clipboard API. Отмена и ручное выделение ссылки цели не создают. Повтор в течение 650 мс подавляется. |

В каждой контактной цели повтор того же действия в течение 650 мс подавляется. Контактные цели отражают намерение связаться. В цели передаётся только `vehicle_id` при наличии.

После сохранённого согласия счётчик запускается с `defer: true` и получает ручной первый `hit`. SEO canonical остаётся без параметров. URL счётчика берёт путь из canonical и только допустимые `utm_source`, `utm_medium`, `utm_campaign`, `utm_content`, `utm_term`, `yclid` из открытой страницы. Дубли, прочие параметры и фрагмент исключаются. В реферере передаётся происхождение источника без пути и параметров. Рекламные ссылки должны содержать только заранее согласованные значения меток. Сайт не сохраняет метки отдельно и не добавляет их в сообщения. Если посетитель покидает посадочную до согласия, её метки не переносятся. [Метод hit](https://yandex.ru/support/metrica/ru/objects/hit.html), [правила обработки меток](https://yandex.ru/support/metrica/ru/general/source-tags).

## Подготовка к индексации

- Перед отправкой карты сайта проверьте опубликованные главную, четыре карточки, `/robots.txt`, `/sitemap.xml` и отсутствующий адрес. Убедитесь, что HTTPS имеет действительный сертификат, редиректы ведут на основной домен, а отсутствующий адрес возвращает HTTP 404.
- В [Google Search Console](https://search.google.com/search-console) добавьте ресурс с префиксом `https://xn--80aafa3dxak.xn--p1ai/`. Выберите HTML-файл или метатег, опубликуйте только подлинное значение, подтвердите права, затем отправьте `https://xn--80aafa3dxak.xn--p1ai/sitemap.xml`. В «Проверке URL» запросите индексирование главной и карточек.
- В [Яндекс Вебмастере](https://webmaster.yandex.ru/) добавьте тот же HTTPS-адрес, подтвердите права HTML-файлом или метатегом, отправьте карту в разделе «Файлы Sitemap» и добавьте канонические страницы в «Переобход страниц».

Адрес пункта выдачи хранится в `company.pickup` в `fleet.json`. Подтверждённый email для связи и обращений хранится в `legal.email`. Эти данные используются в контактах, подвале и реквизитах. В структурированных данных адрес описан как пункт выдачи.

## Открытые вопросы по обработке персональных данных

По подтверждению владельца, фотографии документов поступают от клиентов через Авито и WhatsApp и остаются в переписках. Владелец не сохраняет их отдельно и подтвердил отсутствие фотографий документов клиентов в iCloud Photos. iCloud Mail используется для обращений по персональным данным.

До утверждения политики нужно уточнить локализацию и возможную трансграничную обработку по каждому каналу, условия GitHub Pages, Cloudflare, Apple Find My и iCloud Mail, а также работу Авито и WhatsApp с локальными копиями, кешем и резервными копиями. Остаётся сверить сроки хранения, порядок удаления и запись уведомления Роскомнадзора с фактическими процессами. [Подробные вопросы и технический аудит](docs/privacy-draft.md)
